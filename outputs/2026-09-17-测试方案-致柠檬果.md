## 0. 一句话

被测的是一个「多人决策协作中转站」的后端：**人**发起事项 → **代理**通过 MCP 拉任务、
提交立场 → 平台调模型做摘要和收敛判定 → 收敛了出决议草案等**人**拍板。
你要验的是：**它在你机器上能不能起来、能不能走通、会不会给出错的结果。**

> 要测成功路径，得先让事项跑起来（B 组）。

### A7 MCP 通道：握手 + 工具清单

```bash
SID=$(curl -s -D - -o /dev/null -X POST http://127.0.0.1:8000/mcp/ \
  -H "Authorization: Bearer $T" -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"t","version":"1"}}}' \
  | tr -d '\r' | awk -F': ' 'tolower($1)=="mcp-session-id"{print $2}')
echo "会话: $SID"

curl -s -X POST http://127.0.0.1:8000/mcp/ \
  -H "Authorization: Bearer $T" -H "mcp-session-id: $SID" \
  -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","method":"notifications/initialized"}' >/dev/null

curl -s -X POST http://127.0.0.1:8000/mcp/ \
  -H "Authorization: Bearer $T" -H "mcp-session-id: $SID" \
  -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list"}'
```
**期望**：拿到 `mcp-session-id`；工具清单**恰好 12 个**：

```
list_pending_tasks  get_task  submit_output  get_matter_status     （任务流水线 4）
declare_item  submit_stance  read_stance  get_summary
ask_participant  decide_item  get_digest                            （立场层 7）
list_items                                                          （1）
```

**判分要点**：数量不符（多一个少一个）、或 `initialize` 拿不到会话 id，
都算 **P0** —— 这直接决定代理能不能接进来。

## 4. B 组 · 依赖真模型（**自己申请一个 key 即可**）

> **B 组要一个人配合：** 你需要**两个代理账号**（脚本已造好 `smoke_alice` / `smoke_bob`），
> 它们会通过 MCP 各自拉任务、提交立场。
>
> **密钥怎么来**：去 **https://platform.deepseek.com** 自己申请一个（步骤见 §2.3 第 1–5 步）。
> **不用等 owner 发** —— 这一步不该成为阻塞点。
> 拿到 key 后**第一件事是跑 §2.3 第 4 步那条 `/models`**，确认你账号能用的模型 id，
> 再填进 `.env`。**别照抄我的 `deepseek-flash`。**

### B1 让事项跑起来，首轮问题由模型生成

用网页登录（管理员），建一个事项，选 `smoke_alice` + `smoke_bob` 为参与人，
**问题列表留空**，然后点「开始」。

**期望**：几秒后事项进入「收集中」，两位参与人各拿到 1 个任务，
**首轮问题是模型生成的**（不是空白、不是错误）。

### B2 两个代理提交立场

用 `scripts/smoke_two_agents.py`（把 A2 的两个令牌传进去）：

```bash
SMOKE_BASE=http://127.0.0.1:8000 \
SMOKE_TOKEN_ALICE=<…> SMOKE_TOKEN_BOB=<…> \
.venv/bin/python scripts/smoke_two_agents.py
```
**期望**：两行 `submitted`。

### B3 轮次摘要 + 收敛判定

**期望**：事项离开「收集中」；摘要里有五块内容：
`共识 / 分歧 / 盲点 / 待答问题 / 收敛结论`。
`收敛结论` 取四个值之一：`continue` / `provisionally_ready` / `converged` / `blocked`。

**判分要点（这才是你要盯的）**：
- 摘要**不能出现人名或 id**（应该是「一方 / 另一方」这类匿名措辞）
- 摘要内容要**对得上**两位代理交的东西，不能是空话套话
- 若收敛结论是 `continue`，管线**会自动开下一轮**并下发新任务 —— 这是设计行为

> ⚠️ 这一段的成功/失败**依赖模型输出**，不完全确定。若模型返回不合规的 JSON 而
> 被系统拒收，属于**可接受**（系统会重试并最终给出失败原因）；但如果出现
> **500 / 未捕获异常 / 事项卡死在中间态**，那是 **P0**，立刻报我。

### B4 一页纸

```bash
curl -s -X POST http://127.0.0.1:8000/mcp/ -H "Authorization: Bearer $T" \
  -H "mcp-session-id: $SID" -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"get_digest","arguments":{"matter_id":"<事项 id>"}}}'
```
**期望**：返回里同时有 `current_round` / `decision` / `open_items` 三节，
外加 `consensus_points` / `divergences` / `blind_spots` / `open_questions` / `convergence`。
`decision` 此时应是 `null`（还没出决议草案）。
**里面不该出现 `user_id` / `confidence`**。

### B5 决议草案 → 人拍板 → 终态 ✅ 已验（2026-09-17，柠檬果）

**口径更正**（柠檬果实测）：`converged` 与 `provisionally_ready` **都会**生成决议草案
（`hub/api/pipeline.py:484-487` 两者都放行）。区别在后续路径：`converged` 自动进
`awaiting_decision`；`provisionally_ready` 需发起人在网页先点「接受」才进拍板。

构造方法（柠檬果验证过）：让两位代理在同一轮交**完全一致**的立场 →
`provisionally_ready` → 草案生成 → 网页 `accept` → `awaiting_decision`。

拍板接口：`POST /api/items/{id}/decide`，入参
`{"decision":"approved|modified|rejected","expected_version":N}`。
**期望**：发起人拍板成功 → 事项终态（**无需重启**——拍板后即入后台队列推进，
与网页同一链路）；非发起人拍板 → 403；不可逆事项经 API/MCP → 403
「不可逆事项须在网页由发起人本人确认」——不可逆事项只能由发起人在**网页**完结
（2026-09-17 裁定 2）。

## 5. 已知现象（**看到这些别当 bug 报**）

| 事项变成「已阻塞」 | 可能是轮次上限、模型出题失败、或**僵持判定**（本轮立场与上轮无任何差异）。看 `blocked_reason` 字段 |

## 6. 报问题的格式

请按这个格式提，缺字段我会回头问：

```
【P?】一句话结论
- 环境：机器 / OS / Python 版本 / 提交 sha（git log --oneline -1）
- 前置：做了什么、什么状态
- 复现步骤：贴命令原文
- 实际结果：贴原始输出（原文，不要转述）
- 期望结果：你认为应该是什么，依据是什么
- 是否稳定复现：每次都这样 / 偶尔 / 只出现过一次（很重要！）
- 影响：挡住继续测 / 结果不可信 / 只是难看
```

**优先级自己先判**（我来复核）：
- **P0**：起不来 / 鉴权能被绕过 / 500 或未捕获异常 / 事项卡死在中间态 / 测试数字与我给的不一致
- **P1**：功能路径走不通但可绕开 / 错误码或文案与文档不符 / 摘要内容明显不对
- **P2**：文案、提示语、文档过期、界面难看

**「重跑一次就绿了」会让你以为是环境问题**。现在这条路径已经堵死。
