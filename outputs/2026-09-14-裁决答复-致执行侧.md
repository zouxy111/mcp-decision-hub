> 【依赖前两项：云端 API 与 MCP 接入层】依据：outputs/协作中转-技术方案-v1.md 第四节。
> 实现载体（仓库已具备，不引入新依赖）：langgraph>=1.2.11 + langgraph-checkpoint-sqlite。

> **收敛判据已按审计改写（原方案有错）**：原方案用软共识度 CD 作主指标有两个硬伤——① CD 需数值偏好向量，而立场是类别型（support/oppose/conditional/abstain/need_info），类别型算距离=造新指标而非用成熟算法；② 参与人 2–5 人（hub/domain/participants.py:3-4 硬性），n 小则 CD 高度量化（2 人二值只剩 0/1），μ=0.85 在此规模无意义。
> 改写后：**主指标改为桥接共识（跨阵营共同点）**——只有它能挡住「代理互相讨好导致的假收敛」；CD 仅作辅助且需先定义类别型距离；最保守选项：先不换指标，继续用现有 LLM 四态。
> 注意：现有 `hub/domain/convergence.py` 是 LLM 四态字符串校验（continue / provisionally_ready / converged / blocked），`RoundSummary.convergence` 落库（hub/db/models.py:144）。换指标会动 `hub/graph/matter_graph.py:122-124` 的路由与一批测试，成本不低。
>
> **外层轮次编排**：Round 0 登记事项→广播；Round N 各方**并行**产出立场→提交→云端算收敛；收敛→生成待确认摘要→人点头；不收敛→判「有新增信息吗」：没有则判僵持、**立即拉人，不空转**，有则只回传差异点进下一轮；达轮次上限→强制拉人（**接现有换人流程 `hub/api/reassignment.py`，FR-16，不要另起一套**）。
> **内层拉取节奏**：基础间隔+指数退避；空闲降频；urgency=high 或 deadline 临近提频；有活跃轮次提频、等人工降频。仓库已有分级重试退避（现已落地为 `hub/domain/retry.py`），**不要重写**。
> **硬规则**：并行表态不串行（串行会锚定）；每轮必须带去新信息；不重推全部立场。超时记 missing、不默认同意——仓库已解决（PRD FR-14，scheduler 记 timeout 不伪造），本项只需确认新模型沿用。
