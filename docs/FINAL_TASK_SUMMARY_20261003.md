## 📋 方案一：批处理与上下文压缩

### 核心问题

**你的原始需求**：
> "我希望无需每次有新请求就单独运算，而是对新内容进行总结，内容较多时排队，定期通过 MCP 协议将数据分发至各 agent 完成交换。"

### 解决方案

#### 1️⃣ 批量处理（解决频繁运算）

**从"来一个处理一个"改为"攒一批处理一次"**

```
时间窗口批处理：
09:05  Alice 提交 → 记录，等待
09:08  Bob 提交   → 记录，等待
09:12  Carol 提交 → 记录，等待
       ↓
       [15分钟窗口]
       ↓
09:15  批量处理 3 人 → LLM 一次调用
09:16  MCP 分发结果给所有 Agent
```

**效果**：
- LLM 调用 **↓ 90%**
- 成本 **↓ 60-80%**
- 并发压力 **↓ 85%**

#### 2️⃣ 上下文压缩（解决内容膨胀）

**多轮对话智能压缩，不会无限增长**

```
第 1 轮：10人 × 200字 = 2000字
  ↓ AI 压缩
摘要 1：500字（提炼核心）

第 2 轮：摘要1 + 新观点 = 2500字
  ↓ AI 压缩
摘要 2：800字（累积关键信息）

第 3 轮：摘要2 + 新观点 = 2800字
  ↓ AI 压缩
摘要 3：1000字（持续优化）
```

**效果**：
- Token 消耗 **↓ 60%**
- 关键信息不丢失
- 上下文可控

#### 3️⃣ 定期分发（解决同步问题）

**云端主动标记，Agent 定期感知**

```
云端处理完成
  ↓
标记所有 Task 状态为 "ready"
  ↓
Agent 定期检查（如每 5 分钟）
  ↓
发现新内容，立即展示
```

**效果**：
- 信息同步及时
- 不增加服务器负担
- 用户体验流畅

### 配置建议

| 会议规模 | 参与人数 | 批处理窗口 | 压缩阈值 |
|---------|---------|-----------|---------|
| 小型 | 3-5人 | 5分钟 | 不压缩 |
| 中型 | 6-15人 | 15分钟 | 3轮后压缩 |
| 大型 | 16-50人 | 30分钟 | 2轮后压缩 |

### 实施计划

**6周，分4个阶段**：
- Week 1-2：批处理基础
- Week 3-4：上下文压缩
- Week 5：分发优化
- Week 6：生产验证

## 📋 方案二：邀请链接与自动注册

### 核心问题

**你的优化需求**：
> "希望领导使用时无需处理复杂的健全操作，将权限进一步开放，把创建新事项等设置选项向 MCP 开放，可通过本地 agent 设置云端 agent。通过邀请链仅生成一个邀请链接，进入本地 agent 后会进行绑定，记录本地 agent 提交的信息。"

### 解决方案

#### 核心机制：一句话发起 + 点链接加入

```
┌─────────────────────────────────────────┐
│         领导本地 Agent                   │
│                                         │
│  领导："发起 Q1 战略会议，邀请 Alice、Bob" │
│         ↓                               │
│  Agent 引导对话收集信息                  │
│         ↓                               │
│  MCP: create_collaborative_matter()     │
│         ↓                               │
│  云端自动生成 3 个邀请链接               │
│         ↓                               │
│  Agent 展示链接，引导分享                │
└─────────────────────────────────────────┘
            ↓
┌─────────────────────────────────────────┐
│       参与者本地 Agent                   │
│                                         │
│  点击链接 → Agent 自动打开               │
│         ↓                               │
│  Agent 引导问卷：姓名 + 初步想法          │
│         ↓                               │
│  MCP: consume_invitation_link()         │
│         ↓                               │
│  云端自动：                              │
│    • 创建账号                           │
│    • 生成 MCP Token                     │
│    • 绑定到本地 Agent                   │
│    • 加入协作事项                       │
│         ↓                               │
│  完成！开始协作                          │
└─────────────────────────────────────────┘
```

#### 1️⃣ 领导发起流程（2分钟）

**优化前**（8步，5分钟）：
1. 打开浏览器，登录 Web
2. 点击"创建事项"
3. 填写表单
4. 选择参与者
5. 配置参数
6. 点击创建
7. 通知参与者
8. 等待注册

**优化后**（3步，2分钟）：
1. 对 Agent 说："发起 Q1 战略会议，邀请 Alice、Bob"
2. Agent 引导对话，收集必要信息
3. Agent 返回邀请链接，发给参与者

#### 2️⃣ 参与者加入流程（1分钟）

**优化前**（8步，10分钟）：
1. 收到通知
2. 访问网站
3. 注册账号
4. 等待审核
5. 登录
6. 找到事项
7. 点击加入
8. 开始协作

**优化后**（3步，1分钟）：
1. 点击邀请链接
2. Agent 引导：输入姓名
3. 自动加入，开始协作

**总体改善**：
- 操作步骤：16步 → 6步（**↓ 63%**）
- 操作时间：15分钟 → 3分钟（**↓ 80%**）
- 学习成本：**大幅降低**（自动引导）

#### 3️⃣ 两种协作模式

**会议模式（Meeting Mode）**：
- 实时同步立场
- 快速收敛决策
- 适合：战略会、紧急讨论

**项目模式（Project Mode）**：
- 异步提交观点
- 深度思考调研
- 适合：长期规划、跨时区协作

#### 4️⃣ 新增 MCP 工具

| 工具 | 用途 | 调用方 |
|------|------|--------|
| `create_collaborative_matter()` | 创建事项并生成邀请链接 | 领导 Agent |
| `get_invitation_info()` | 查询链接信息（预览） | 参与者 Agent |
| `consume_invitation_link()` | 消费链接，自动注册加入 | 参与者 Agent |
| `start_collaborative_matter()` | 启动协作 | 领导 Agent |
| `get_my_collaborative_matters()` | 查询我的协作列表 | 所有 Agent |

#### 5️⃣ 安全机制

**邀请链接保护**：
- ✅ 短有效期（3天）
- ✅ 单次使用（每个链接只能用1次）
- ✅ 6位短码（如 xY9kL2）
- ✅ 即时撤销（领导可撤销）

**自动注册保护**：
- ✅ IP 限流（每小时最多5个）
- ✅ 审计日志（完整记录）
- ✅ 异常检测（自动告警）

### 实施计划

**7周，分4个阶段**：
- Week 1-2：邀请链接基础（短链生成 + 验证 + 自动注册）
- Week 3-4：引导式问卷（对话流程 + Agent 集成）
- Week 5-6：会议模式（实时同步，可选）
- Week 7：生产验证

**阶段性交付**：
- ✅ Week 4：核心功能可用（邀请链接 + 项目模式）
- ⭐ Week 6：增强功能上线（会议模式）
