## 1. 任务定义：什么叫「从执行到交付」

### 1.1 目标

把 **中转站 v1 · 立场层协作**（里程碑事项 `rtI7lI`）从「代码实现大半、卡在同步与决策」推进到「**全部子项完成标准达成 + 全量门槛绿 + 已进入 `main`**」。

### 1.2 交付的定义（三条同时满足才算交付）

| # | 定义 | 判定方式 |
|---|---|---|
| D1 | `rtI7lI` 下**每一个**子事项的**完成标准**（不是标题）逐条达成 | 对照事项描述逐字核，证据写到 `文件:行号` |
| D2 | 全量测试通过 + lint 干净 | 见 §6.1 门槛命令，**必须自己亲眼看到汇总行** |
| D3 | 代码进入 `main` | PR 已合并，或分支已 push 且 PR 已开并说明未合并原因 |

**不算交付的情形**（明确列出，避免自我说服）：

- ❌ 「代码写好了但没跑门槛」——未达成 D2
- ❌ 「测试绿了但完成标准没逐条核」——未达成 D1
- ❌ 「大部分做完了，剩下 2 项下次」——未达成 D1
- ❌ 「我判断这一项按标题已经算完成」——**违反 §3.2，直接判不合格**
- ❌ 「验证工作是另一个 agent 做的，我没复核」——验证必须由**未参与实现**的独立执行者做并留下证据（见 §6.3）

### 1.3 不适用的做法

- **不做**重构式「顺手改好」——只做完成标准要求的改动 + 必要的技术债清理（清单见 §4.6）
- **不做**超出 PRD 2.2 非目标的功能（个人模型上传 / 服务器 Agent 文件读写 / Agent 间直连推送 WebSocket / OAuth2.1 / Keycloak / Temporal / PostgreSQL / MinIO）
- **不做**给历史数据「猜测式回填」（见 §3.4）

### 3.4 ⛔ 明确禁止的取巧做法

1. **禁止启发式回填历史授权字段**。存量 `stances.authority` 是自由文本，无法可靠判定「本人提交」还是「代理提交」。
   → 猜错 = **伪造授权记录**，比留空危险得多。
   → 正确做法：新枚举列置 `NULL` + **原值保留到 `authority_legacy`**（自由文本、只读）+ 迁移记审计。
2. **禁止把历史空值按新语义标注**。存量 `approved_at` 为空的老记录，**绝不能**在界面上写「可能是代理提交」——那会把当年的**本人提交误记成代理承诺**（语义污染）。
   → 只允许中性措辞且**只在内部视图**：「该记录早于本版本，无确认时间留痕」。
3. **禁止用「降级为跳过」绕过验收**。若某条完成标准做不到，**必须**登记为「未达成 + 原因」并上报，不得改写成「已完成」。

### 6.3 独立变异检验（不可省略）

**定义**：由**未参与该模块实现**的执行者，**独立地破坏实现**，确认目标测试**变红**，然后还原并做哈希校验。

**为什么必须**：本项目实测一次改写 6 个变异，**查出 3 条空洞测试**：

| 测试 | 问题 | 修法 |
|---|---|---|
| 迁移备份探测 | 删早返回**仍绿**（同名秒级时间戳被覆盖 → 文件数恒 1），且**跨秒会 flaky** | 改断言 `(name,size,mtime_ns)` 快照 + 把已有备份 mtime 钉到 2000-01-01 |
| 失败无半成品 | 删显式 `ROLLBACK` **仍绿**（连接池还池时默认 rollback 兜底） | 诚实收窄语义 + 改名 + 注释写明由两机制共同保证 |
| 外键恢复 | 删「OFF + 恢复」整段**仍绿**（测试从不把 FK 置 OFF，`==1` 恒真） | 加真追踪 `_ForeignKeysTracer` + 改名 |

**空洞测试的三种典型形态（照清单查）**：
1. **断言恒真**（同名文件被覆盖 → 数量恒为 1，且跨秒 flaky）
2. **被兜底掩盖**（连接池默认 rollback 兜了显式 ROLLBACK 的底）
3. **被测对象从未进入目标状态**（测试自己从不把 FK 置 OFF）

**完成标志**：每个变异都有「目标测试变红」的证据 + 真红原因 + 还原后全量仍绿 + 生产文件哈希逐字节一致。

**⚠️ 组长的判断也可能是错的**：实测中被证伪过（预期「去掉迁移 DDL 的 CHECK 会让 `test_stance_model.py` 枚举断言变红」—— 实际不会，那 4 条走 ORM `create_all`，与迁移 DDL 无关）。

## 7. 已知陷阱与红线

### 7.1 环境陷阱（本机实测）

| # | 陷阱 | 影响 | 正确做法 |
|---|---|---|---|
| 1 | **`core.autocrlf = true`** | 磁盘文件是 **CRLF**，Git blob 是 **LF** | **绝不能把磁盘文件内容直接推上仓库**（会把 CRLF 灌进去，PR 显示整文件改写）。推 `git show HEAD:<path>` 的 blob，或 `git clone -c core.autocrlf=false`。**校验**：本地 `git rev-parse HEAD:<path>` 的 blob SHA 与远端 API 的 `sha` 相等 = 逐字节一致 |
| 2 | **沙箱出口代理坏** | `HTTP_PROXY`/`HTTPS_PROXY` 指向每会话换端口的本地代理，git smart-HTTP 走它报 `CONNECT tunnel failed 502` | 跑 git/gh 前 **`unset` 代理变量直连** |
| 3 | **网络间歇性抽风** | 直连约 1/3 请求超时（`000`，19~25s）；同端点时而全通时而全断 | **一切网络操作带 5~6 次重试**。`git push` 实测前 4 次全失败、**第 5 次成功** |
| 4 | **沙箱拦 GUI 启动 + job 对象连带杀子进程** | 直接 `Popen(chrome)` 命令期间进程存活、命令结束归 0 | `os.startfile(url)` 经 shell 转交，由 explorer 创建窗口 → 存活 |
| 5 | **Bash 工具 PATH 极简** | `ls` / `head` / `tail` / `mkdir` / `which` / `dirname` / `sed` / `grep` / `cat` / `rm` **全都不存在** | 写文件用 Write 工具；列目录/查内容用 Glob/Grep/Read。**别写 shell 管道** |
| 6 | **PowerShell 工具基本不回传 stdout** | 执行有效但读不到输出 | 需要输出就**落盘再 Read** |
| 7 | **敏感内容审批门** | 某些文件经连接器/读取工具返回 `SENSITIVE_APPROVAL=TIMED_OUT`（已知：`tests/conftest.py`、`tests/web/test_timeout_flow.py`） | 换通道（本地 clone 后用 Read）通常能拿到；**不要重试同一个通道** |
| 8 | **GitHub 连接器只读** | `create_branch` → `403 Resource not accessible by integration` | `permissions` 字段反映的是**用户权限**，**不是令牌授权范围**。该令牌是 GitHub App installation token，缺 `contents: write` |
