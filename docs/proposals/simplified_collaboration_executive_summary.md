# 领导简化协作方案 - 一页纸决策简报

**核心诉求**: 领导只用本地 Agent，一句话发起协作，参与者点链接自动加入

---

## 一、当前 vs 优化 🎯

### 现状（8 个步骤）

```
领导端：
1. 打开浏览器，登录 Web
2. 点击"创建事项"
3. 填写标题、目标、背景
4. 选择参与者（需要知道用户名）
5. 配置轮次、超时等参数
6. 点击"创建"
7. 分别通知每个参与者
8. 等待参与者注册加入

参与者端：
1. 收到通知
2. 打开浏览器，访问网站
3. 点击"注册"
4. 填写注册信息
5. 等待管理员审核
6. 登录后找到事项
7. 点击"加入"
8. 开始协作

总耗时：领导 5 分钟 + 参与者 10 分钟 = 15 分钟/人
```

### 优化后（3 个步骤）

```
领导端：
1. 对 Agent 说："我想召开关于 Q1 战略的会议，邀请 Alice、Bob、Carol"
2. Agent 引导对话，收集必要信息（目标、背景）
3. Agent 自动创建并返回邀请链接，发给参与者

参与者端：
1. 点击邀请链接
2. Agent 引导：输入姓名，简单说明想法（可选）
3. 自动加入，开始协作

总耗时：领导 2 分钟 + 参与者 1 分钟 = 3 分钟/人
```

**改善**: 操作步骤 **↓ 63%**，时间 **↓ 80%**

## 二、技术方案 🏗️

### 核心机制：邀请链接 + 自动注册

```
┌──────────────────────────────────────────────────┐
│                领导本地 Agent                     │
│                                                  │
│  对话："发起 Q1 战略会议，邀请 Alice、Bob"         │
│         ↓                                        │
│  MCP: create_collaborative_matter()              │
│         ↓                                        │
│  返回：3 个邀请链接                               │
└────────────────┬─────────────────────────────────┘
                 ↓
┌──────────────────────────────────────────────────┐
│                  云端服务器                       │
│                                                  │
│  1. 创建事项（draft 状态）                        │
│  2. 生成短链（6位，如 xY9kL2）                    │
│  3. 每个参与者一个专属链接                        │
│                                                  │
│  https://hub.tdp-demo.work/join/xY9kL2           │
│  https://hub.tdp-demo.work/join/aB3mN7           │
│  https://hub.tdp-demo.work/join/pQ8rT4           │
└────────────────┬─────────────────────────────────┘
                 ↓
┌──────────────────────────────────────────────────┐
│              参与者本地 Agent                     │
│                                                  │
│  点击链接 → Agent 自动打开                        │
│         ↓                                        │
│  引导式问卷：姓名 + 初步想法                       │
│         ↓                                        │
│  MCP: consume_invitation_link()                  │
│         ↓                                        │
│  云端自动：                                       │
│    • 创建账号（alice_xY9kL2）                    │
│    • 生成 MCP Token                              │
│    • 绑定到本地 Agent                            │
│    • 加入协作事项                                │
│         ↓                                        │
│  完成！可以开始协作                               │
└──────────────────────────────────────────────────┘
```

### 新增 MCP 工具（4个）

| 工具 | 用途 | 调用方 |
|------|------|--------|
| `create_collaborative_matter()` | 创建事项并生成邀请链接 | 领导 Agent |
| `get_invitation_info()` | 查询链接信息（预览） | 参与者 Agent |
| `consume_invitation_link()` | 消费链接，自动注册加入 | 参与者 Agent |
| `start_collaborative_matter()` | 启动协作 | 领导 Agent |

### 数据库表（新增2个）

```sql
-- 邀请链接表
CREATE TABLE invitation_links (
    link_id VARCHAR(8) PRIMARY KEY,      -- 短链 ID（如 xY9kL2）
    matter_id VARCHAR(26) NOT NULL,      -- 关联事项
    inviter_id INTEGER NOT NULL,         -- 邀请人
    role VARCHAR(20) DEFAULT 'participant',
    max_uses INTEGER DEFAULT 1,          -- 单次使用
    used_count INTEGER DEFAULT 0,
    status VARCHAR(20) DEFAULT 'active', -- active | expired | exhausted
    expires_at TIMESTAMP NOT NULL        -- 默认 3 天
);

-- 链接消费记录
CREATE TABLE invitation_consumptions (
    link_id VARCHAR(8) NOT NULL,
    user_id INTEGER NOT NULL,
    user_name VARCHAR(100) NOT NULL,
    consumed_at TIMESTAMP NOT NULL
);
```

```
领导: "我想召开关于 Q1 战略的会议，邀请 Alice、Bob、Carol"

领导: "确认"

       邀请链接已生成（有效期3天）：
```

## 四、两种协作模式 🔄

### 会议模式（Meeting Mode）

**特点**: 实时同步，快速决策

```
适用场景：
✅ 战略决策会
✅ 紧急事项讨论
✅ 需要快速拍板

运作方式：
1. 所有人加入后会议启动
2. 每人提交立场后立即处理
3. 云端实时生成摘要
4. 其他人立即看到更新
5. 2-3 轮快速收敛
```

### 项目模式（Project Mode）

**特点**: 异步协作，深度思考

```
适用场景：
✅ 长期项目规划
✅ 跨时区团队协作
✅ 需要深度调研

运作方式：
1. 所有人加入后项目启动
2. 各自提交立场（24-48 小时窗口）
3. 窗口结束后批量处理
4. 云端生成综合摘要
5. 进入下一轮（每轮 2-3 天）
```

**自动识别**：Agent 根据对话内容推荐模式

## 五、安全机制 🔒

### 邀请链接保护

| 机制 | 说明 | 效果 |
|------|------|------|
| 短有效期 | 默认 3 天 | 防止长期泄露风险 |
| 单次使用 | 每个链接只能用 1 次 | 防止转发滥用 |
| 专属绑定 | 链接与参与者名称关联 | 可追溯来源 |
| 即时撤销 | 领导可撤销未使用的链接 | 应急响应 |

### 自动注册保护

| 机制 | 说明 | 效果 |
|------|------|------|
| IP 限流 | 同 IP 每小时最多消费 5 个链接 | 防止批量攻击 |
| 审计日志 | 记录所有链接消费行为 | 可追溯审查 |
| 异常检测 | 自动识别可疑行为 | 及时告警 |

## 八、风险与应对 ⚠️

### 主要风险

| 风险 | 影响 | 应对 |
|------|------|------|
| 链接泄露 | 无关人员加入 | 3天有效期 + 单次使用 + 撤销功能 |
| 引导失败 | 用户卡住 | 提供跳过选项 + 降级到 Web |
| 自动注册被滥用 | 系统压力 | IP 限流 + 异常检测 + 告警 |

### 降级方案

如遇问题，用户可随时切换到 Web 界面：

```python
INVITATION_LINK_ENABLED = false  # 一键关闭新功能
```

## 十、决策建议 💡

### 推荐方案

**核心功能优先**（Phase 1 + Phase 2，4周）:
- ✅ 邀请链接
- ✅ 自动注册
- ✅ 引导式问卷
- ✅ 项目模式（异步，使用批处理）

**增强功能可选**（Phase 3，2周）:
- ⭐ 会议模式（实时同步）
- ⭐ 增量摘要
- ⭐ 实时通知

### 实施建议

**Step 1**: 先做 Phase 1 + Phase 2（4周），快速验证

**Step 2**: 小规模试点（5-10 人）

**Step 3**: 收集反馈，决定是否做 Phase 3

**Step 4**: 灰度上线，逐步推广

### 关键指标

上线后监控：
- 邀请链接生成数
- 链接消费成功率（目标 > 95%）
- 用户操作耗时（目标 < 3 分钟）
- 用户满意度（目标 > 4.5/5.0）
