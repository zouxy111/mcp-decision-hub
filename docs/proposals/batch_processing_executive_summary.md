# 集团战略决策会 AI 辅助方案
## 一页纸版本 - 面向领导汇报

---

## 一、应用场景 🎯

**集团战略决策会：多位高管/业务负责人需要达成共识**

```
┌────────────────────────────────────────────────────────┐
│                                                        │
│  各位高管本地与 AI 深度交互（隐私保护）                  │
│           ↓                                            │
│  提交结论性观点到云端（纯文本）                          │
│           ↓                                            │
│  云端 AI 批量分析，生成共识/分歧/追问                    │
│           ↓                                            │
│  定期分发给所有参与人                                    │
│           ↓                                            │
│  多轮收敛 → 主持人拍板                                  │
│                                                        │
└────────────────────────────────────────────────────────┘
```

---

## 二、核心优化 ✨

### 优化 1：批量处理（解决频繁运算问题）

**现状**：来一个人提交，就运算一次  
**优化**：攒一批人一起处理

| 时间点 | 原方案 | 新方案 |
|--------|--------|--------|
| 09:05 Alice 提交 | 立即运算 | 记录，等待 |
| 09:08 Bob 提交 | 立即运算 | 记录，等待 |
| 09:12 Carol 提交 | 立即运算 | 记录，等待 |
| 09:15 窗口关闭 | - | **批量运算一次** |

**效果**：
- LLM 调用次数 **减少 90%**
- 成本大幅降低
- 服务器压力降低

### 优化 2：上下文压缩（解决内容膨胀问题）

**现状**：多轮对话后，上下文越来越长  
**优化**：智能压缩，只保留核心要点

```
第 1 轮：10人 × 200字 = 2000字
  ↓ AI 压缩
摘要 1：500字（提炼核心）

第 2 轮：摘要1 + 10人新观点 = 2500字
  ↓ AI 压缩
摘要 2：800字（累积关键信息）

第 3 轮：摘要2 + 10人新观点 = 2800字
  ↓ AI 压缩
摘要 3：1000字（持续优化）
```

**效果**：
- Token 消耗 **减少 60%**
- 上下文不会无限膨胀
- 关键信息不丢失

### 优化 3：定期分发（解决信息同步问题）

**现状**：Agent 需要频繁轮询  
**优化**：云端主动标记，Agent 感知新内容

```
云端处理完成
  ↓
标记所有参与人"有新内容"
  ↓
Agent 定期检查（如每 5 分钟）
  ↓
发现新内容，立即展示给用户
```

**效果**：
- 信息同步及时
- 不增加服务器负担
- 用户体验流畅

## 四、配置建议 ⚙️

### 不同规模会议的参数

| 会议规模 | 参与人数 | 批处理窗口 | 压缩策略 |
|---------|---------|-----------|---------|
| 小型 | 3-5人 | 5分钟 | 不压缩 |
| 中型 | 6-15人 | 15分钟 | 3轮后压缩 |
| **大型（集团级）** | **16-50人** | **30分钟** | **2轮后压缩** |

### 建议配置（集团战略会）

```
批处理窗口：30分钟
  理由：给高管充分思考时间

触发条件：
  - 收齐 100% → 立即处理
  - 达到 80% + 等待 5分钟 → 处理
  - 窗口到期（30分钟）→ 强制处理

压缩阈值：第 2 轮开始压缩
  理由：战略会通常 2-3 轮即可收敛
```

## 七、风险与应对 ⚠️

### 主要风险

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 批处理延迟 | 用户等待 | 提供"快速模式"开关，小会议可关闭 |
| 压缩质量 | 信息丢失 | 设置压缩比监控 + 人工审核机制 |
| 系统复杂度 | 维护成本 | 功能开关 + 完整测试 + 详细文档 |

### 降级方案

如遇问题，可随时一键切回原模式：

```python
BATCH_PROCESSING_ENABLED = false
CONTEXT_COMPRESSION_ENABLED = false
```

系统立即恢复到当前稳定版本。

## 八、决策建议 💡

### 方案对比

| 维度 | 当前方案 | 优化方案 | 差异 |
|------|---------|---------|------|
| 成本 | 高 | 低 60% | ✅ 显著节省 |
| 性能 | 并发高峰 | 平稳 | ✅ 服务器友好 |
| 体验 | 即时 | 延迟 15-30分钟 | ⚠️ 需权衡 |
| 扩展性 | 受限（50人+困难） | 良好（支持大规模） | ✅ 面向未来 |

### 建议

**推荐采用优化方案**，理由：

1. ✅ **成本可控**：大规模会议成本降低 80%
2. ✅ **技术先进**：批处理 + 压缩是行业标准做法
3. ✅ **风险可控**：增量实施 + 降级开关
4. ✅ **业务契合**：战略会本就是异步深思熟虑，15-30分钟延迟可接受
