# 产出人物决策模型

## 安装本 skill

装两个（推荐 —— 一个负责连上，一个负责产出决策模型）：

```bash
mkdir -p ~/.workbuddy/skills && curl -fsSL https://hub.tdp-demo.work/static/skills/skills.tar.gz | tar xz -C ~/.workbuddy/skills
```

只装这一个：

```bash
mkdir -p ~/.workbuddy/skills && curl -fsSL https://hub.tdp-demo.work/static/skills/build-decision-model.tar.gz | tar xz -C ~/.workbuddy/skills
```

校验 `ls ~/.workbuddy/skills/build-decision-model/SKILL.md`；客户端不刷新就重启一次客户端。
不想用命令行，也可以打开 <https://hub.tdp-demo.work/static/skills/index.html> 自行下载。

## 何时用 / 何时不用

**用**：要给一个人建一份「他在新问题上会怎么判」的说明书；要把散落的行为痕迹蒸馏成可被 agent 消费的结构化上下文；要复用一份已有的决策模型去建新的。

**不用**：只想要一句人设标签；没有可核对的材料、只能靠印象写；对象不同意被建模。

## 与相关 skill 的边界（先划清，否则会做重）

| skill | 干什么 | 产出 |
|---|---|---|
| **本 skill** | **从已有材料产出**一份新的决策模型 | 一份 12 章的模型页 |
| `decision-model-interview` | **对本人做结构化访谈**，校准**已有**模型 | 采访采集项（V1…Vn）+ 级别升降 |

## 第 0 步：素材盘点，并把覆盖度公开

**这一步的产出会写进正文，不是内部笔记。** 覆盖率不公开，读者会把推断当事实用。

建两张表：

**① 来源表**（每条来源标权重）

| 来源 | 内容 | 权重 |
|---|---|---|
| 一手行为留痕（决策记录、里程碑日志、切实际的取舍） | … | **最高**（行为 > 自述） |
| 实时决策留痕（记忆库/台账） | … | 高 |
| 本人自述式材料（方法论笔记） | … | 高，但属自述 |
| 对外口径材料（简历、汇报） | … | 中（**可能择优**，要标注） |
| 二手知识（读书笔记、书库导入） | … | **不作为本人经验的证据** |

**② 覆盖度表**（给数字，不给感觉）

写清：语料总量、按类型分布、实际纳入多少条、占比多少、**关键缺口是什么**。

> ⚠️ **一手 / 二手必须分离**（这是一条有过真实教训的纪律）。把读书笔记、书库导入的知识当作「本人的经验来源」，会产生**归因污染**：模型里会出现一堆「他很看重 X」，而其实他只是读过一本讲 X 的书。**二手材料只能作为候选假设，不能单独作为某人决策原则的证据。**

**素材不足时不要硬写。** 把缺口列进「信息缺失清单」，并写清「补什么能提升哪一章的精度」。

## 第 1 步：建立证据分级标记，并全程贯彻

三条标记（沿用这套已被验证的分级）：

| 标记 | 含义 | 来源 |
|---|---|---|
| `[实]` | 已确认的稳定事实 | 一手行为留痕；本人明确表述过的契约 |
| `[复]` | 跨场景重复出现的行为模式 | 多条独立材料交叉印证 |
| `[推]` | 基于现有证据的推断 | **可反驳**，不得被下游当事实消费 |

**硬规矩**：正文每一条判断都要带标记；引用这份模型时**必须保留标记**，不得把 `[推]` 级内容转述成已确认事实。

**降级规则**（要有明文，否则模型会腐化）：某条 `[复]` 级内容在 N 个月内未复现 → 降为 `[推]` 并标注；某条 `[推]` 被本人反驳 → 降级或删除，**并写进变更日志**。

## 第 2 步：提炼心智模型（核心原则 M1…Mn）

### 筛选：三重验证，缺一不取

一条观察要成为「心智模型」，必须同时过三关：

1. **跨域复现** —— 至少在 ≥2 个**不同领域**出现过（只在一个项目里出现的做法，是习惯，不是原则）
2. **生成力** —— 能用它**推断**他在一个全新问题上的立场
3. **排他性** —— 不是「所有聪明人都这样」。不满足就降级为常识，别写进原则

**按排他性强度排序输出**，不要按重要性排序。

### 写法：每条固定五段

```
### M<n>｜<一句话内核> `[实|复|推]`

**内核**：<把这条原则说清楚，一到三句>

**跨域复现**：<领域 A 的实例> · <领域 B 的实例> · <领域 C 的实例>

**生成力**：<面对某类新问题，他的第一反应会是什么>

**排他性**：<多数人会怎么做，他哪里不一样>

**失效条件**：<什么场景下这条不成立 —— 必须写，没有失效条件的条目不可信>
```

**「失效条件」这一段是这份文档区别于「人设小作文」的地方。** 缺了它，条目就变成了不可反驳的赞美。

**来源要诚实标注**：如果某条其实是**习得后的纠正原则、不是既有本能**，就直说（依据可以是本人自述的一次失败案例恰好是这条的反面）。这种诚实会大幅提升整份模型的可信度。

## 第 3 步：决策启发式（IF-THEN 表）

把可执行的快速规则写成表，**每条都能被当成一行代码读懂**：

| # | IF（触发条件） | THEN（默认动作） | 级别 |
|---|---|---|---|
| H1 | <可识别的触发> | <具体动作> | `[实]` |

要点：
- IF 必须是**可识别的条件**，不是「当他觉得……」这种内部状态。
- THEN 必须是**可执行的动作**，不是「他会更谨慎」。
- **给规则补前置条件**：有些规则（如「同类缺陷出现 ≥2 次就做机制修复」）隐含了一个更难的子问题——**怎么判定「同类」**。若本人承认卡点正在这里，就把前置条件写进该行，否则这条规则只在「已经认出来」时才生效。

---

## 第 4 步：典型决策流程

把可复用的流程画成**编号步骤 + 关键约束 + 来源案例**。

- 标注**顺序不可换**的地方，以及**在什么条件下才启动**这个流程（「适用于……」）。
- 关键约束单独写，例如：「第③步未完成前不进入第⑤步」「第⑥步禁止和稀泥」。
- **保留本人的自命名**（如果他把这套做法叫某个名字），那是他的语言，比你的转述更准。

---

## 第 5 步：优先级取舍序（约束冲突时怎么办）

这是最难写、也最容易被证伪的一节（实测：某份模型连续两轮在这节被推翻）。

- 区分两类：**硬约束**（不参与权衡，任一不满足直接淘汰）与**可权衡项**（之间会真实取舍）。
- 给每一项标**证据**，纯推断的明说。
- 如果存在一条「比取舍更前置」的规则——例如规定**从哪里开始**而不是「怎么权衡」——单独立成**序 0**。理由：顺序反了（先动手造，再回头找现成的），后面的序再正确也白搭，**成本已经付在错误的起点上**。
- 给每条附**适用条件**：它什么时候才生效（例如「只有当同类需求确定会出现第二次时」）。**是条件型信号，还是模糊感觉？**——如果是后者，明说「判据未显式化」，并记为一个风险点。

---

## 第 6 步：例外与反模式

**两件事分开写：**

**① 主动声明的例外**：什么场景下**不**按上述流程走，以及**理由**（用他自己的表述）。典型：探索性 POC、紧急救火、一次性脚本。

**② 反模式清单**：他明确要**做减法**的行为。分组（过程类 / 结构类 / 工程类 / 表达类），每条最好是**有事故支撑的具体行为**，不是抽象格言。
> 例：「静默补默认值 / 把字符串『解析』成结构——那是编值」远好于「要严谨」。

---

## 第 7 步：内在张力（保留矛盾，不做调和）

**这一步是模型深度的来源。** 同一个聪明人在不同场景下会做出相反选择；把这些矛盾并排写出来，并给出一条**化解规则（推断）**：

| # | 张力 A ↔ B | 表现 | 化解规则（推断） |
|---|---|---|---|
| T1 | <做法 A> ↔ <做法 B> | <两处相反的实际表现> | <分界线是什么> |

规则：
- **不要和稀泥**地把 A 和 B 说成「其实是同一件事的两个面」——除非有证据（实测中这种调和曾被本人直接证伪两次）。
- 化解规则的**分界线要具体到可判定**（例如「是否会出现第二次同类需求」是计数型信号，可用；「看情况」不可用）。
- 如果某条调和被证伪，**保留证伪记录**，不要悄悄改掉。

---

## 第 8 步：矛盾点与信息缺失（逐条处理，附校准方式）

**① 材料之间的不一致**（逐条）

| # | 冲突点 | 各材料各说什么 | 我的处理 | 依据 |
|---|---|---|---|---|

处理原则写死：**以可验证的实测/最新记录为准**；旧条目视为历史事实源；**不越权改写**别人的口径（发现问题只追加，不自动替换）。

**② 信息缺失清单**（逐条，必带「校准方式」）

| # | 缺失项 | 影响 | 我的假设 | 校准方式 |
|---|---|---|---|---|

**缺口必须写出来**（没有一手自述材料 / 没有失败决策记录 → 幸存者偏差 / 无非工作域记录 / 无第三方视角 / 无时间稳定性证据）。
**每写一个假设，就要写清「补什么能验证它」。**

**贯穿全模型的处理原则**，建议照抄这几条：

1. **矛盾保留而非调和** —— 矛盾本身是信号
2. **推断必须显式标注** —— `[推]` 不得被当事实消费
3. **原始记录优先于二手画像** —— 画像的 `updated` 字段可能滞后
4. **不越权改写** —— 只追加，不自动替换他人的口径
5. **一手 / 二手分离** —— 二手知识只作候选假设
6. **敏感内容不复写** —— 发现凭据、患者信息等，**只记录「存在与位置」，不在模型内复现其值**，并升级为待处置项（建议轮换 + 清除 + 加写入守卫）

## 第 9 步：迭代与验证机制

**① 修正门槛**（同时满足才允许自动应用）

- 有明确证据
- 置信度 ≥ 门槛 —— ⚠️ **门槛通常不是定值，随影响面浮动**（大事要求更高）。写成常数是常见错误。
- 不改变硬约束 / 权限 / 伦理边界
- 不扩大适用范围

否则 → 转人工审核。

**② 触发条件**（什么事件会触发修订）：出现真实的取舍冲突事件 / 某条推断被反驳 / 某条 `[复]` 长期未复现 / 新增决策域 / 定期回溯。

**③ 待验证清单**（把「采集到的事实」与「我的解读」**分列**）

| # | 采集到的事实（本人明确选择） | 我的解读 | 置信度 | 状态 |
|---|---|---|---|---|

解读**一律标 `[待验证]`，且不改正文** —— 等第二次独立印证或本人确认后再升级。这一条是防止「采访一结束就把自己的推论写成事实」的关键闸门。

**④ 变更日志**（倒序，每次修订一条）：日期 + 版本 + 改了什么 + **来源** + **证据等级** + 级别升降。
**把被证伪的推断留在日志里**（「原推断 X 被证伪，替换为 Y」）。证伪记录是这份文档最有价值的部分之一 —— 它证明了建模过程会自我修正。

**⑤ 记录你自己的建模偏置**

诚实写下「我倾向把观察归因到哪里，而真实卡点常常在哪里」。例如某个真实案例里反复出现的模式是：*建模者倾向把行为归因到下游（执行 / 机制 / 载体），真实形态常是上游判据缺失或按对象分层*。

**这一条决定这份模型能不能自我改进。** 后续建模时先问：**是没看出来，还是看出来了没做，还是判据根本没说清？**

---

## 第 10 步：诚实边界（不可省）

明确写出：

- 本模型**不能预测**具体选择，只给方向与优先级倾向
- 哪些章节是推断、未经本人确认
- 受哪种偏差影响（幸存者偏差：只看见成功的做法）
- **适用范围**：是职业决策模型还是完整人格？⚠️ 有些人的答案是「**两套，工作归工作**」——那模型就**不得外推到非工作域**。别默认能迁移。
- **失效条件**（最重要的边界）：什么情境下模型最不准（常见答案：*时间紧、有人在催* —— 即压力下判断一致性下降）。如果多条独立证据都指向「判据靠直觉 → 压力下失效」，把这一模式显式记下来。
- 第三方视角（如果有）：他人怎么评价他的判断方式。**这往往能暴露本人和建模者都看不到的成本**（例如「要求太高太细」——某种特质在独自作业时是优势、在协作时是成本）。
- 证据截止日期；超过一定时间未更新的条目按规则降级。

## 可选扩展章节：引入外部框架时

可以引入心理学/类型学框架（如荣格八维）作为**词汇表**，但必须：

1. **声明该框架信效度有限**，只作可反驳假设；
2. 全部结论标 `[待验证]`，**不得升级为正文判断**；
3. 方法与主模型同纪律：**事实与解读分列**，用「具体事件 + 强制选择 + 含证伪选项」的题去问，而不是问卷式自评；
4. 记录**推翻了自己几处初始推断**——推翻数比确认数更能说明方法有效。

## 三条最容易被忽略、但决定成败的纪律

1. **证伪优先于证实。** 主动去找反例。找不到反例才允许保留一条规则。一条被证伪并**记录在案**的推断，比十条被印证的推断更能提升模型可信度。
2. **建模者自己的偏置要写进文档。** 否则同一类错误会在每一版里重演。
3. **不确定就标出来，别抹平。** 一份 60 分但**标注诚实**的模型，比一份 90 分但混着未经标注推断的模型有用得多 —— 后者会让下游把猜测当事实执行。

## 方法来源（本 skill 的依据）
