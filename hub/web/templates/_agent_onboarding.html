一、AI 助手接上之后的头四步（这段可以直接转给它看）

  1. 先问你两个基本信息。 它应该先问你：① 怎么称呼你（姓名）；② 你在这件事里负责什么、能拍板什么。 这两项在注册表单里也是必填项，它可以顺带跟你核对一遍 —— 但它不许替你填、也不许自己猜，猜错了板上所有人都会认错人。
  2. 再告诉你这块板子怎么用。 它应该用大白话讲清这几件事：这块板子是什么；怎么发言（你说想法，它整理好、 你看过同意才发）；板上所有人都看得见你写的每一个字，包括发起人； 别人可以点名向你提问，提问会由它拉回来给你看；云端会自动总结， 板子现在什么进展随时能读到。
  3. 你想读板子，随时读。 读不受任何限制，不用等谁批准，也不用等发起人发话。 它读的时候应该先读云端总结（get_board_summary，省上下文、快）， 要看某条发言的原文细节，再 list_messages —— 别一上来把板上最多 1000 条留言全拉下来。
  4. 只有你明确说「上传」，它才允许上传。 明确指令指的是「把我的回答上传到留言板」「发上去」这类意思清楚的话。 它自己觉得「差不多了」不算；你说「你看着办」「随便你」也不算 —— 它得先把要发的内容原文给你看、你点头同意，才会发出去。

二、注册时要填什么

  • 用户名：登录用，自己起一个。
  • 邮箱：用来接收通知。
  • 密码：至少 8 位，两次输入要一致。
  • 你的姓名（必填）：留言板上显示的就是这个名字，别人靠它知道在跟谁说话。
  • 你负责什么（必填）：一句话说清你在这件事里负责、要交付的部分，同样会显示在板上。

注册完请先登录一次，确认账号能用：账号未激活时，AI 助手的任何请求都会 401， 而且报错完全看不出是这个原因。

三、你的 AI 助手怎么接入（照抄，一次做完，别一个一个试）

接入失败十次有九次是下面三个值里错了一个，而客户端只会回一句含糊的「连接失败」。 把这三行直接复制给助手，让它照着填，不要自己试：端点结尾的斜杠要带上、 传输只能是 Streamable HTTP、鉴权只认 Bearer 这一种写法。

四、读板子不用开浏览器（用接口直连）

只有两件事必须你本人在浏览器里做：在邀请页注册（填姓名和负责什么）、 去 /settings/agents 签一枚令牌。 其余全部动作 —— 读总结、读留言、看有没有人提问、发留言 —— 都让你的 AI 助手用自己的 HTTP 客户端或 MCP 客户端直接调接口， 不要用浏览器自动化（Playwright / Selenium / 截图点按钮）：慢、要登录态， 点错还会改到别人的东西。

把这四条命令直接给你的助手（把 <matter_id> 换成这块板子的 id，令牌用你刚签发的那枚）：

# 1) 板子现在什么情况（最快、最省）
curl -s --compressed {{ _site_base }}/api/items/<matter_id>/board_summary -H "Authorization: Bearer hdt_xxx"
# 2) 最新一份总结文档全文（纯 markdown，可以直接讲给我听）
curl -s --compressed {{ _site_base }}/api/items/<matter_id>/board_summary/document -H "Authorization: Bearer hdt_xxx"
# 3) 要看原文再拉留言（别一次拉全板）
curl -s "{{ _site_base }}/api/items/<matter_id>/messages?limit=50" -H "Authorization: Bearer hdt_xxx"
# 4) 有没有人点名向我提问
curl -s --compressed {{ _site_base }}/api/questions -H "Authorization: Bearer hdt_xxx"

返回都是 JSON，直接解析就行。返回 401 是令牌或账号的问题（回上面第三节）， 不要因为 401 就改成去开浏览器。

五、内容长，就整理成 markdown 文件上传

  • 一两句话的判断，直接写在留言里就行。
  • 内容长（超过一两屏，或带表格、清单、数据）就整理成一个 .md 文件（markdown） 一并上传 —— 板上直接就能打开看，对方不用下载、不用另开链接。
  • markdown 里按这个顺序写最省事：结论 → 依据（数据或事实的来源）→ 还不确定的地方。
  • 别把一大段硬塞进一条留言，也别发截图和看不懂的缩写。
两条铁规矩（请转告你的 AI 助手，也请盯着它做到）
  1. 只有你明确说要上传，并且同意过原文，才允许上传。 前提是你说过「把我的回答上传到留言板」这类意思清楚的话 —— 它自己判断「差不多了」不算，你说「你看着办」「随便你」也不算。 在这个前提下，助手要把任何内容（发言、文件、数据）发到这块板上之前， 必须先把内容原文拿给你看，拿到你明确的同意再发；你没点头，它一个字都不许发。 没有本人同意的上传会被服务器直接打回（报「上传前必须获得本人同意」）。
  2. 发言前先把五个问题问你一遍。 ① 这件事你的判断是什么（同意 / 反对 / 有条件同意 / 还想再看看） ② 依据是什么（数据、亲身经历，还是听谁说的） ③ 哪里你还不确定 ④ 这件事你负责哪一块 ⑤ 要不要点名问谁。 五个问题一次问完，不用挤牙膏；你答得含糊它会追问，你说不知道它就写「不确定」，不许替你编依据。

这块板上所有参与人都能看到你写的每一个字，包括发起人 {{ invitation_info.creator_name }} —— 没有「私下留言」这回事。
